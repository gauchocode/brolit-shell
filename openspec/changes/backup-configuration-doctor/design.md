## Context and authorization

Implements only approved Phase A of Admin `docs/plan/active/2026-10-backup-configuration-doctor.md`. The separately untracked Borg rollout plan is not part of this change.

## Decisions

- Use installed Python 3.10+ and PyYAML >= 5.4 only (the observer's documented fleet profile: 5.4.1/6.0.x); absent, older or malformed versions yield `parser_unavailable`. Fleet-version execution is verified separately (remediation Phase 4). Never install dependencies. Existing observation parsing cannot prove non-use and is not modified.
- Define `flat-static-v1`, not a general Borgmatic validator. Support literal flat configuration and simple scalar constants with identifier references. Inspect all values, including hook strings, for references; interpolation in keys is unsupported. Reject unknown fields, tags, aliases, merges, multiple documents, non-string keys, nesting over 24 and unknown interpolation. Accept `checks`/`check_last` shapes and Borg runtime placeholders only in `archive_name_format`/`match_archives` (a bare `{name}` that is a defined constant stays a constant reference), so every Brolit template as generated is analyzable. Hooks are accepted and scanned; bodies that are empty, have a non-literal command word, or (as written, or after constant expansion with each constant resolved once and one shared per-profile character budget) mention `database`, Borgmatic configuration locations, `config.yml`/`config.yaml` or configuration readers yield `hook_intent_unknown` (ambiguous, blocks proposals). This denylist only gates an informational proposal; any future apply requires an exact allowlist. Programs run by hooks are not inspected and are declared as `hook_programs_not_inspected`. Recognized database declarations remain ambiguous without external intent evidence. No environment is read for resolution.
- Production discovery is fixed to `/etc/borgmatic/config.yaml`, direct `.yml`/`.yaml` children of `/etc/borgmatic.d`, `/root/.config/borgmatic/config.yaml` and direct children of `/root/.config/borgmatic.d` (never `$HOME`/`$XDG_CONFIG_HOME`). Other files and nested shapes explicitly make discovery incomplete; one failing location does not drop the others. Explicit `--config` paths used by Brolit are not inventoried (`explicit_config_paths_not_inspected`). No arbitrary production root argument. Test mode substitutes an isolated fixture root, requires a marker, and refuses euid 0, any effective capability and relative roots before any filesystem access. Any profile that is not fully analyzable suppresses every proposal in the run (it may include another profile's constants); cross-file reference analysis is not implemented. Core dumps are disabled.
- Open config ancestors by directory descriptor with no-follow/nonblocking flags, and check a bounded mount table before each access. Only recognized local filesystem types are allowed; unknown, remote and automount boundaries are refused without probing. Files must be regular, single-link and bounded. Never follow source paths in production: without an authorized local metadata policy, report unknown. Source-path findings keep the profile ambiguous/invalid and incomplete but do not block the database-constant proposal, which they are independent of. Test mode can exercise local missing/present source checks beneath its marked root with the same no-follow/mount checks.
- Allow a proposal only for a scalar unused `constants.database` with an environment dependency, supported complete reference analysis, no other ambiguous/unsupported evidence (source-path findings excepted) and a byte-preserving single-line block-mapping deletion. Parse and re-inspect the prospective bytes solely in memory; the re-inspection must yield exactly the original findings minus the constant's own (`environment_dependency_unavailable`, `unused_constant_candidate`). Otherwise require manual review. No raw document, values, paths, exceptions or content hashes leave the process.
- Profiles carry `file` (allowlisted basename `[A-Za-z0-9._-]{1,128}`, otherwise `null` with `discovery_unsupported` and no analysis) and a fixed `location` class as the stable operator correlation key; no absolute paths. `profile_id` handles are random invocation-local identifiers. Proposals are informational random identifiers, not repair tokens. Limits: 64 profiles, 256 KiB/file, 8192 YAML events, depth 24, zero aliases, 10-second deadline (single SIGALRM raising a non-`Exception` timeout so per-item handlers cannot relabel it), 256 KiB output, 1 MiB mount table. Process address-space and CPU limits provide additional fail-closed bounds.

## Limitations

Static grammar is independently fixture-tested; this is not certification of Borgmatic 1.9.14 or 2.1.7 (`borgmatic_semantics_uncertified`). Includes, explicit `--config` locations, programs run by hooks, dynamic expansion, application environment availability, database/project correspondence, backup execution and restore health are not established. Any future widening needs fixtures and review. No apply authority exists.
